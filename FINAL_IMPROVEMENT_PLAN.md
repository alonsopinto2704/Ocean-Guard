Keep these items open before claiming PS compliance or field readiness.

### Implementation vision for the next agents

Build a **separate sonar path** alongside Espada's existing RGB camera path. Sonar intensity imagery can support debris detection and object–shadow reasoning; calibrated range/depth pings can support bathymetry. They are different measurements. Do not feed synthetic depth cells into an image detector, turn acoustic darkness into a measured depth, or silently reuse the RGB model as a validated sonar detector. Keep the current simulation working throughout.

The intended flow is: source adapter → validated raw ping/frame plus acquisition metadata → quality and motion checks → sonar-specific intensity processing and/or depth projection → detection or valid depth cells → immutable event/replay record → UI with source, uncertainty and unknown gaps. Preserve raw inputs and processing version so each displayed result can be traced and reproduced.

**Input contract to establish before processing.** A sonar record needs sensor and mission IDs; ping/frame ID and sequence; acquisition timestamp and clock basis; raw intensity or range/depth data with dimensions and encoding; beam/range geometry and metres-per-pixel or per-bin spacing; calibration and coordinate-frame identifiers; AUV position and timestamped heave, pitch, roll and heading with uncertainty; and explicit missing/invalid samples. Mark whether a field is measured, derived or simulated. Reject unsupported encodings, impossible geometry, non-finite values and missing scale/pose when georeferencing requires them. Never substitute a default 2 m cell size for unknown real resolution. Record receive time separately from acquisition time.

**Output contract.** For every accepted record, retain the source IDs, raw reference/hash, preprocessing version, scale transform, valid/invalid mask, quality flags, acquisition time and provenance. A sonar detection must link to its source ping/frame, original-coordinate box or mask, class/score provenance and location uncertainty; a dark region alone is not a detection. A mapped cell must carry depth in metres, coordinates/frame, cell size, uncertainty, source ping IDs and quality. Rejected or missing swaths produce a quality/gap event, not a bathymetry cell. Extend the existing event format additively and keep older saved replays readable.

**Work package A — ingest and geometry.** First add a small, documented sonar fixture format and parser; use real vendor metadata when available and deterministic fixtures until then. Keep side-scan/backscatter intensity and multibeam depth payloads distinct. Define axis directions, positive-depth convention, units, beam origin, pose interpolation window and timestamp ordering in one place. Validate that a known target maps to the same ENU position after resolution changes and that converting a predicted box back to source pixels is reversible within rounding tolerance. Do not enable field-live mode merely because an upload parser exists.

**Work package B — speckle.** Keep the original intensities. Implement a configurable, deterministic edge-preserving baseline on sonar intensity images only; choose the filter and intensity domain from actual data rather than assuming RGB noise statistics. Preserve bright target boundaries and adjacent dark shadows. Store the filter/version and processed preview, then use the *same* transform in sonar training and inference. Unit checks: a flat noisy patch becomes less variable; a small target and its shadow remain visible; constant, empty and saturated frames do not create detections. Evaluation: compare raw versus processed precision, recall, false positives and per-frame latency on held-out speckle strata.

**Work package C — resolution.** Derive physical scale from range/beam metadata. Resample to a documented working scale without warping aspect ratio, with letterboxing/tiles or calibrated multi-scale inference as appropriate; store the inverse transform. Keep original dimensions and metres-per-pixel with every prediction. Unit checks: square and non-square frames, different ranges and resolutions, edge boxes and round-trip coordinates. Evaluation: report metrics separately by resolution/range band and test that the same annotated object retains consistent physical size and mapped position.

**Work package D — acoustic shadows.** Preserve shadow regions as context; do not erase or automatically classify them as debris. Add labeled target-plus-shadow, shadow-only, bottom texture and empty-water examples, with mission/site-level train/validation splits. If a shadow mask or quality flag is used, link it to the source image and distinguish an observed shadow from an inferred object. Unit checks: a dark patch with no target cannot by itself create a positive; a partially shadowed target can still be reviewed; masking never fabricates a depth. Evaluation: count false positives on shadow-only negatives and missed targets on shadowed positives separately.

**Work package E — heave, pitch, roll and gaps.** Synchronize each sonar ping with AUV pose/IMU and calibration before projection. Detect sequence and timestamp gaps, invalid returns, excessive motion and stale/missing pose. Compensate coordinates only when calibration and time alignment support it; otherwise mark the swath degraded or unknown. Never fill a missing swath with the procedural seabed or a neighbor cell. Unit checks: injected heave/pitch/roll moves projected test returns as expected; missing pose and skipped ping IDs yield quality/gap events and zero mapped cells; recovery resumes at the next valid ping without reusing stale attitude. Replay at different seek positions must show the same gaps and quality state.
